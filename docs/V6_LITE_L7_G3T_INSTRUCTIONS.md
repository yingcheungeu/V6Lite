## 第二部分　第十五批：L7 券商端保护单

### 2.1 目标

持仓的止损不能只靠引擎在运行。电脑、Gateway、网络任何一处出问题，券商那边都必须有一张已经确认的止损保护单在等着。这是**实盘的硬性前置条件**。方案沿用 `V6_LITE_REDESIGN.md` 第 8.4 节：GTC Stop-Limit（`STP LMT`）。

### 2.2 先交设计说明（不写代码）

`docs\V6_LITE_L7_DESIGN.md` 至少要回答下面每一项，并逐条给出 IBKR/ib_insync 的依据（官方文档链接或 ib_insync 源码位置）：

1. **订单形态**：
   - 每个持仓一张 GTC `STP LMT` 卖单，`outsideRth=False`，`orderRef` 用持久化的 intent id；
   - 触发价 = 持久化的止损价；
   - 限价 = 触发价 × (1 − `protect_limit_offset_pct`)，这个参数见 2.4 的 John 决定。
2. **不变式（最重要）**：任何时刻，“所有在途卖单的数量（含保护单）”都不得超过“券商的最新持仓”。
   - 推荐方案：止盈触发时，先把保护单数量**减去**这次要卖的股数，拿到券商确认后，再发止盈卖单；止盈成交或撤单之后，再把保护单调整到实际剩余持仓。
   - 如果改用 OCA，必须说明 IBKR 对 OCA 按比例减量的实际行为，以及怎样保证不超卖。
   - 设计中写清楚：在每种中间状态下，最坏情况会卖出多少股。
3. **保护单数量规则：只减不增。**
   - 发现券商持仓小于保护单数量时，**立即**把保护单减下来（减量总是安全的）；
   - 加量或补挂只能在拿到新鲜、完整的证据之后进行：券商持仓、全部在途订单、成交记录三者一致。
4. **各个事件的处理**：
   - 入场部分成交：成交多少就保护多少；
   - TP1 后改为保本价：修改保护单的触发价；
   - 正常停机：撤销 DAY 单，**保留**已确认的 GTC 保护单；
   - 重启：先认领已有保护单，再对账，之后才恢复止盈逻辑；身份或数量不明时不盲目补发；
   - 冻结：保护单处理要服从不变式，P0 卡片写明保护单的状态；
   - 保护单被拒、被撤销、状态不明：停止新开仓，P0 告警，写明有多少股没有保护；
   - 每天对账：检查每个持仓的保护单是否存在、数量是否正确；
   - GTC 单被券商取消（例如公司行动）后的恢复。
5. **触发了但没成交**：价格跳过限价时，保护单已触发却没有成交。说明程序如何发现，P0 卡片的内容是什么（写明操作员该做什么），并且**不自动改用市价单**（7/17 的裁决不变）。
6. **程序化止损和保护单的关系**：两者不能各自发出卖单。说明程序化 STOP 是改为“监控 + 告警”，还是通过修改同一张保护单来实现。
7. **需要 John 在 Paper 中实测的场景清单**，供 G3 使用：
   - 强行结束进程；
   - 断开本机网络；
   - Gateway 重启；
   - 止盈部分成交后的数量协调；
   - 止损触发但未成交；
   - 盘后到第二天开盘时，保护单是否仍在。
8. **改动范围与测试计划**：要改哪些文件和函数；FakeBroker 需要补充哪些能力（改单、GTC、触发、部分成交）；需要哪些测试。

Claude 复核设计说明之后，再按批准的设计实施，作为第十五批。

### 2.3 实施时的约束（预先说明）

- 只增加保护单相关的路径，不改入场逻辑、风控数值和扫描策略。
- 每一项都有聚焦的测试，并且先证明这些测试在实施前的代码上失败。必须包含**超卖反例测试**：对每一个中间状态，断言在途卖单总数不超过持仓。
- 由独立 Agent 复核：从入口到 place/modify/cancel 的每条路径都满足不变式。

### 2.4 需要 John 决定的参数

- **`protect_limit_offset_pct`**：止损触发后，限价比触发价低多少。
  - Claude 的建议是 **3%**。依据：BT-1 中几次止损当天的开盘跳空在 1–4% 之间。偏移太小，跳空时保护单触发了却成交不了，等于没有保护；偏移大一些，最坏的成交价会更差。
  - 无论取多少，都**不用市价单**。
- **测试模式参数**：建议 3 股，倍数 0.3 / 0.3 / 0.5 / 0.8。
