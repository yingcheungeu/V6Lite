## 0 John 的决定（原文记入报告）

> John 选择方案 B：券商端保护单改用止损市价单（STP），只用于保护单。入场和止盈继续使用限价单。不启用“被拒后自动重挂”。

依据：`docs/V6_LITE_BATCH21_RESEARCH_AND_OPTIONS_2026-10-08.md`。10/8 G3-T 中，IBKR 以“限价偏离止损价太多”拒绝了 3% 偏移的 STP LMT。IBKR 没有公开距离上限，而且止损限价单在开盘跳空时可能不成交。John 已知并接受的代价：STP 触发后按市价成交，跳空或停牌复牌时，成交价没有下限。

## 1 订单合同

| 项 | 要求 |
|---|---|
| 类型 | SELL `STP`，`auxPrice` = 已入账的止损价，按 0.01 向下取整（沿用现有取整规则）；不设 `lmtPrice` |
| 有效期 | `GTC`，`outsideRth=False`（只在常规交易时段触发） |
| 身份 | account、clientId、conId、orderRef、orderId、permId 全部沿用第二十批的强身份核验；类型核验改为 `STP`，不得再把 `STP LMT` 当作有效的保护单 |
| 唯一例外 | 全系统只有 `purpose=PROTECT` 的订单可以是 STP。入场、止盈和其他任何卖出，仍然只能是 LMT。测试断言：除保护单外不存在任何非 LMT 订单；`MKT` 调用次数为 0 |
| 自动重挂 | 不实现。券商明确拒绝保护单时，按第二十批的拒单路径：P0，冻结入场，首选人工处置 |

## 2 配置

- `[protection]` 新增 `order_type`，v1 只允许 `"STP"`，默认 `"STP"`；纳入配置指纹。
- `limit_offset_pct` 删除。配置里出现它就报 `CONFIG ERROR`，并在错误信息中写明“保护单已改为 STP，不再使用 limit_offset_pct，请从配置中删除”。**不得静默忽略。**
- `trigger_unfilled_p0_seconds` 保留，含义改为：价格已到止损价，并且在常规交易时段内，保护单超过这个秒数仍有剩余未成交，就发 P0（STP 理论上会立即成交；长时间不成交意味着停牌、交易暂停或其他异常）。
- 更新全部示例配置：`paper.toml`、`paper_delayed.toml`、`paper_test.toml`、`paper_g3n.toml`、`live.toml`。
- 在报告中列出 John 的两份运行配置（`v6lite.g3t.toml`、`v6lite.paper.toml`）需要删掉的行，**但不要修改它们**，由 John 自己改。

## 3 必须覆盖的路径（逐条列出改动和对应测试）

1. 首次提交（入场成交回调内）、部分入场后加量、保本价修改（改 `auxPrice`）、止盈前减量与恢复、末股撤单。
2. 原生订单快照的强身份与价格核验（STP 没有限价，不得因为限价为空就判为身份不符）。
3. 重启认领、退休身份（第二十批新增）、停机保留 GTC、release 核验。
4. 触发监测：
   - 价格到止损价时发 P1（保留，文字改为“已到止损价，券商止损市价单应在成交”）；
   - 超过 `trigger_unfilled_p0_seconds` 仍有剩余，发 P0；
   - 删除“现价低于限价”那一条判断。
5. 成交记录：保护单成交时，记录止损价、成交均价，以及滑点（美元和基点），写入审计 `PROTECT_FILL`，并在日报的“券商端保护”一栏列出当日每笔止损的滑点。G3 需要这些数据。
6. 卡片：保护相关的卡片去掉“限价”字段，改为“止损价（触发后市价成交）”。“止损触发但限价未成交”卡片改为“止损已触发但未成交”，写明可能的原因（停牌或交易暂停），以及人工处置步骤。
7. 已有 `STP LMT` 保护记录（例如旧状态库）：不得修改，也不得自动迁移；发现时发 P0“旧类型保护单，需人工处理”。**John 的正式 Paper 状态没有保护记录，G3-T 状态会归档，所以只需要安全拒绝即可。**
8. 数据库 schema：保护表新增 `order_type` 列，旧行迁移时标为 `STP LMT`，再走第 7 条。
