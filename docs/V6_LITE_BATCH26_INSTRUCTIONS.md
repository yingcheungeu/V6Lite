## 0 背景

第二十五批报告第 5 节确认：IBKR 的当日成交查询（executions）不覆盖昨天的入场成交，所以过夜持仓的三项证据中 `full_exec=False`。b25 的处理方式是：稳定的过夜持仓不算核验失败，但**不能加量、不能重建保护单、不能发止盈、不能解除旧事件**。结果是，过夜持仓重启后只剩券商端的止损，永远不会自动止盈。

正式策略的止盈价位是 +3 / +5 / +8 ATR，持仓经常跨好几天，所以这个限制必须在 G3-N 之前解决。

## 1 调查（先交调查结论，再动生产代码）

1. **IBKR 能查到多早的成交：** 查官方资料，说明 `reqExecutions` / ExecutionFilter 的时间范围到底能回溯多久（当天、7 天，还是取决于 TWS 设置），附链接。本机 ib_insync 0.9.86 的实际行为也要写清楚。查不到就写“未知”，不要猜测。
2. **只靠当天证据够不够：** 评估下面这些数据组合起来，能不能对过夜持仓给出足够的完整证据：
   - 入场时已经持久化的账本成交（fills 表，包含 execId、permId、数量、价格）；
   - 当天的持仓和工作单；
   - 当天的成交（只覆盖今天）。
   
   **判断标准：** 券商持仓 = 账本 qty_open；GTC STP 保护单身份强核验通过、数量等于 qty_open；当天没有任何无法归属的成交或外部卖单。
3. **说明风险：** 列出“依赖已持久化的历史账本”这种方式有哪些风险，以及如何把它们挡住。例如：停机期间在 TWS 手动交易、在别处登录下单、状态库被替换或回滚。

## 2 实施要求（以调查结论为准，下面是底线）

- **过夜止盈证据：** 历史部分由已持久化的账本成交提供，当天部分仍由完整的三项查询提供。两部分合起来，并满足第 1.2 节的全部判断标准时，才允许止盈和保本价修改。
- **不放宽的地方：**
  - 任何一项不一致，都保持 b25 现在的行为：只保留止损、冻结止盈、发卡片；
  - 不能因为“没查到”就推断“没有发生”；
  - `S+T+X ≤ P` 以及所有强身份门槛不变。
- **保护单数量与持仓不一致时**（例如停机期间 TWS 手动卖出了一部分），按现有的外部卖单和冻结规则处理，不自动修复。
- **卡片：** 过夜持仓第一次启用止盈之前，发一条 INFO：“过夜持仓已通过历史账本 + 当日三项核验，自动止盈恢复”，写明用到的证据。核验不通过时发 P1，写明哪一项不一致。
