Claude 用 FakeBroker 复现了第十二批的冻结场景和“止损被拒”场景。手机实际收到的卡片如下：

| 场景 | 原英文正文中的关键信息 | 第十二批手机卡片 |
|---|---|---|
| 冻结（P0 “V6-Lite no longer manages AAPL”） | 账本 20 / 券商 17；**这些订单没有被撤销、仍可能成交**：`v6l-46b1… SELL 6`、`v6l-orphan01 SELL 4`；**先确认 AAPL 没有任何在途订单，然后**再保护或平仓；券商显示 0 股且没有在途单后，执行 `release AAPL` | “自动退出或止损保护受阻 AAPL……必要时人工保护或平仓”。没有数量，没有订单号，也没有“先撤单、再平仓”的顺序。如果操作员在仍有卖单在途时直接平仓，可能多卖成空头。 |
| 止损被拒（P0 “exit refused AAPL STOP”） | 需要卖 20 股，可卖 0 股；去 TWS 核对持仓，必要时在 TWS 里设保护 | 标题是“V6-Lite 运行告警”，正文是“出现需复核的运行异常 AAPL；详情见本机日志”。**最紧急的告警，卡片却最含糊**，连“止损没有发出去”都没有写。 |

操作员常常只能看手机，日志在家里电脑上。卡片要求只写三栏，**可以短，但不能把具体信息和操作顺序省掉。**

第十二批指令里写了“细节只写日志”，这句话写得不准确，导致了这个结果，责任在 Claude，不在 Codex。本批纠正：**省掉的应该是解释性的文字，而不是数字、订单号和操作步骤。**

## 1 修复项

| # | 严重度 | 内容 |
|---|---|---|
| **H1** | P1 | **每一类 P0/P1 告警都要有自己的中文标题**，不再让不同事件共用“运行告警”“订单状态需核对”这类标题。先在报告里列出 Q-B 告警清单中每个家族对应的中文标题，一对一，不重复。 |
| **H2** | P1 | **“发生了什么”必须写出关键事实**，按告警类型包括：<br>• 标的；<br>• 阶段（STOP/TP1…）；<br>• 关键数字：账本 vs 券商的股数、需要卖 vs 可以卖的股数、剩余股数、价格；<br>• 涉及的订单号：最多 5 个，超出部分写“另有 N 个”；<br>• 异常代码，例如 `clear-anomaly` 需要用到的代码。 |
| **H3** | P1 | **“你要做什么”必须保留原文中的操作顺序和具体命令**，写成编号步骤，不能写成“必要时……”这样的笼统一句。例如冻结：<br>1）在 TWS 确认或撤销仍在途的 AAPL 订单：v6l-…（卖 6）、v6l-orphan01（卖 4）；<br>2）确认 AAPL 没有任何在途订单**之后**，再人工保护或平仓；<br>3）券商显示 0 股、且没有在途订单后，在本机运行 `release AAPL`。<br>止损被拒：写明“**止损未发出**：需要卖 20 股，可卖 0 股”，接着写在 TWS 核对持仓、必要时人工设止损的步骤。 |
| **H4** | P1 | **长度规则**：<br>• 每一栏不超过 600 字符；整张卡片不超过 1500 字符；<br>• 超出时，先截短解释性文字，再截订单列表（保留前 5 个订单）；**数字和步骤编号不得截掉**；<br>• “详见本机日志”只能作为补充，不能作为一栏的全部内容。 |
| **H5** | P2 | 第十二批的 G8 在 Windows 上，只要遇到一个读不到命令行的 python 进程（例如管理员权限运行的 python），正式运行就会被拒绝。保持这种保守做法，但拒绝信息里要写明 PID 和处理方法（例如“确认 PID 1234 是什么进程，或关闭它后重试”）。dry-run 的 P1 卡片同样写明。 |
